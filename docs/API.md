# API Reference

## Base

API prefix:

```
/api/v1
```

Health endpoints are also available outside the versioned API.

## Authentication

Protected endpoints require:

```
X-Telegram-Init-Data: <Telegram WebApp initData>
```

The header contains Telegram-signed data generated by the Mini App. The server verifies the signature and binds the request to the existing Telegram user.

Do not send a bot token or database credentials from the Mini App.

## Health

### GET /health

Basic API health.

### GET /health/live

Liveness probe. It does not prove PostgreSQL is ready.

### GET /health/ready

Readiness probe. It checks PostgreSQL connectivity and the migrated schema.

Example successful response:

```json
{
  "status": "ok",
  "database": "ok",
  "revision": "..."
}
```

### GET /api/v1/health

Returns API liveness and the configured application version.

## Protected endpoints

All endpoints below require Telegram Mini App authentication.

### GET /api/v1/me

Returns the authenticated application's Telegram-linked user.

### GET /api/v1/economy

Returns the user's economy account.

### GET /api/v1/economy/transactions?limit=50

Returns recent coin transactions. The API validates the requested limit.

### GET /api/v1/games/profile

Returns the authenticated user's game profile.

### GET /api/v1/reputation

Returns the user's community reputation.

### GET /api/v1/achievements

Returns achievements available to the user.

### GET /api/v1/achievements/progress

Returns achievement progress for the authenticated user.

### GET /api/v1/shop/items?category=<category>

Returns shop items, optionally filtered by category.

### GET /api/v1/shop/inventory

Returns the authenticated user's inventory.

### GET /api/v1/conversations/{other_user_id}/messages?limit=50

Returns messages for a conversation involving the authenticated user and the requested other user.

The API must not allow a client to read an unrelated user's conversation.

## Request IDs

Every HTTP response should include:

```
X-Request-ID: <uuid>
```

A valid client-supplied UUID may be preserved. Invalid or missing request IDs are replaced with a server-generated UUID.

Use the request ID when reporting a server error so operators can locate the corresponding structured log event.

## Error contract

The API is being migrated toward a stable machine-readable error contract. Clients should not depend on Python exception text or stack traces.

Until the unified error handler is complete, clients should treat the existing `detail` field as human-readable and avoid parsing it for business logic.

## CORS

Configure exact frontend origins with:

```env
API_CORS_ORIGINS=https://your-mini-app.example
```

Do not use a wildcard origin together with credentials in production.

## Security rules

- Never trust Telegram identity fields supplied outside signed initData.
- Never expose BOT_TOKEN.
- Never expose DATABASE_URL.
- Never return stack traces to clients.
- Keep protected endpoints behind the authentication dependency.
- Keep Mini App and API communication HTTPS in production.
